# DSH WorkBuddy Subscription

在 DeepSeek Harness 的 **设置 → WorkBuddy** 里登录 WorkBuddy，查看账号剩余积分与可用模型——和 Codex 订阅插件的设置页是同一套体验。登录成功后，账号的模型会出现在对话输入框的模型选择器中。

## 它和 `dsh-workbuddy-connect` 的关系

上游协议从 `dsh-workbuddy-connect@0.7.3` **作为库**引入：HTTP 客户端、模型目录解析、回环 shim、pi-ai 适配器。它的 bundle 行**不会**被启用，所以它的桌面端登录探测和它自己的设置卡片都不会出现。

本插件只负责一件事——**登录**。`dsh-workbuddy-connect` 只能采用 WorkBuddy 桌面端已经登录的凭据，这在无图形界面的 Linux 服务器上等于没有入口。这里由宿主驱动腾讯自己的插件登录流程：

```
POST {endpoint}/v2/plugin/auth/state?platform=…   → { state, authUrl }
浏览器打开 authUrl（登录页）
GET  {endpoint}/v2/plugin/auth/token?state=…      → 轮询到令牌（code 11217 = 尚未完成）
GET  {endpoint}/v2/plugin/login/account?state=…   → 账号、昵称、企业 id
```

凭据写入**插件自己的**凭据文件（`$DSH_HOME/.workbuddy-auth.json` / `.workbuddy-ai-auth.json`），而不是任何桌面端的文件。这个路径同时也是库刷新令牌、以及 `logout` 删除的路径，因此登录、续期、退出三者指向同一份文件。

## 版本

| 组件 | 版本 |
| --- | --- |
| 本插件 | 1.0.0 |
| `dsh-workbuddy-connect`（依赖库） | 0.7.3 |
| 已验证的 DSH | 0.2.1-alpha.2 |

`dsh-workbuddy-connect@0.7.3` 的 peer 声明锁定 `@deepseek-ai/dsh-llm@0.2.0-rc.2`，与 0.2.1-alpha.2 不匹配。因为它在这里是**传递依赖**（不在 profile 的直接依赖表里，也不在 patch 行里），安装时的 peer 检查不会评估它；但它的**运行期**兼容性属于未验证组合，宿主日志里可能出现相关错误。若该库加载失败，`workbuddy-subscription` 这一行会激活失败，设置页不会出现——这一点如实报告，不做静默降级。

## 双区域

国内版 `workbuddy`（`copilot.tencent.com`）与国际版 `workbuddy-ai`（`www.workbuddy.ai`）是两个独立账号体系，设置页用 tab 分开，各自登录、各自读积分、各自刷目录。两边都登录时两个模型分组同时可用。

凭据的区域由 `domain` 决定（`workbuddy.ai` 及其子域 = 国际版，其余 = 国内版）。区域不符的凭据会在写入前被拒绝，并给出明确原因，不会让一个国内版账号悄悄顶替国际版。

## 设置页

三张卡片：账号（登录态、令牌有效期、凭据路径）、积分（合计、各套餐余量、到期时间）、模型。

模型目录是一张四列表格——**模型 / 上下文 / 输出上限 / 倍率**，数字列右对齐并用 `tabular-nums`，所以可以顺着列往下比。几处刻意的取舍：

- **身份占两行**：上行是显示名，下行是模型 id。上游会给不同模型起同名（实测国内版 `hy3` 与 `hy3-x` 都叫 "Hy3"，国际版两个 `deepseek-v4.1-flash*` 都叫 "Deepseek-V4.1-Flash"），只显示名字就分不出来。
- **倍率只留乘数**：国内版目录给的是 `x0.29 credits`，国际版给的是 `x0.29`。宿主用上游库自带的 `normalizeCredits` 去掉单位词，客户端也容忍两种拼法，因此无论宿主是哪一版都能正确显示。
- **「免费」写在倍率列**，不放在名字旁：它是一条价格，写在价格列；而那一格写「—」会被读成「未知」。倍率已失效的行显示「未知」，而不是重复一个过期的折扣价。
- **容量按数值本身选进制**：`65536` 显示 `64K`、`393216` 显示 `384K`，而 `512000` 保持 `512K`。一律除 1000 会把 64K 说成 66K，一律除 1024 会把 512K 说成 500K。
- **目录超过 8 个模型时出现筛选框**（按名字或 id 过滤）。实测量级：国内版 18 个、国际版 27 个。
- **兜底目录会标成警示色**：内置占位目录不是账号的真实目录，不该和上游目录长得一样。

## 每日签到（仅国内版）

「积分」卡底部有一行签到，显示连续天数、今日可得积分和一个按钮。按钮文字优先用上游给的 `claim_button_text`（实测是「立即领取」）。

**为什么要手动点**：签到是**真实领取奖励**的写操作。所以这里刻意不做自动签到——

- 只有点击才发写请求；
- 写之前宿主会**再读一次状态**，今天已签到就直接返回「已经签到过」，不会重复写；
- 同一产品同时只允许一次签到在飞；
- 签到成功后会把缓存的积分读数作废，卡片随即刷新。

国际版没有这个活动（同一接口返回 `active: false`），所以那一行只在「国内版」tab 出现，国际版调用会被直接拒绝。

> 如果你想要「每天自动签到」，那属于另一种取舍：它会替你在你没看的时候动账号。需要的话可以做成显式开关，但默认应该保持关闭。

## 端点

客户端通过共享 `/api` 通道调用，令牌不进入浏览器：

| 端点 | 作用 |
| --- | --- |
| `status` | 两个产品的登录状态、令牌有效期、凭据路径、目录来源、适配器注册结果 |
| `login/start` / `login/status` / `login/cancel` | 浏览器授权登录的发起、轮询、取消 |
| `login/submit` | 粘贴凭据登录（平铺或 `auth`/`account` 嵌套格式） |
| `logout` | 删除本插件保存的凭据 |
| `usage` | 剩余积分（10 秒内复用上一次读数，避免重绘重复计费） |
| `models` | 账号模型目录，可要求刷新 |
| `refresh` | 主动刷新目录 |

## 国际版的渠道校验（HTTP 400 / 11128）

国际版端点对请求做**官方客户端校验**。内联的 `dsh-workbuddy-connect@0.7.3` 原文只发 `X-IDE-*` / `X-Product` / `X-Requested-With` 这组头，2026-10-27 实测国际版对**任何**请求都回：

```
HTTP 400  {"code":11128,"msg":"request illegal", …}
这次调用没通过渠道校验，可能不是官方客户端发出的。请用官方版本重新发送。
```

连「一条 user 消息、无工具、max_tokens: 8」都会被拒，所以不是参数 / 模型 / 工具 / 令牌的问题——同一个令牌读目录和积分都正常。

**修复**：补上 WorkBuddy 自己客户端会发的**三个**会话头，且必须三个齐全（单独任何一个、任意两个都仍然 400；`X-Agent-*` 三个头加了也没用）：`X-Conversation-ID` / `X-Conversation-Request-ID` / `X-Conversation-Message-ID`。国内版不发这些头也能用，补上之后仍然 200。

三个 id **每次请求都用新的 UUID**。这一点很关键：不能从对话内容推导出跨轮稳定的 id——DSH 的子 Agent 与主 Agent 共享同一段对话但**工具集不同**，如果上游按会话 id 关联工具定义，第二个 Agent 拿着不同的工具去用同一个 id，正好就是「工具定义不合规，请新建任务重试」的形态。上游 0.7.9（issue #139）也是这么修的，并记录了网关并不按 id 保存会话历史，所以随机 id 不丢东西。

## 国内版曾有一个只在真实路径上出现的 400

「请求被拦截，请重新发送」这句话是 `11128` 的界面文案，但它有**两个**完全不同的成因，很容易混：

| 成因 | 修法 |
|---|---|
| 缺三个 `X-Conversation-*` 会话头 | 见上一节，请求头补齐 |
| 消息里出现 `role: "developer"` | 请求体把它改写成 `system` |

第二条只影响**国内版**：国际版路径会调用 `prepareChatBody` 做改写，国内版路径原来只处理了推理档位。同一个函数还负责把对象形式的 `tool_choice` 拍平成字符串（国内版对对象形式会回 `11101 cannot unmarshal ... of type string`），以及强制 `stream: true`。现在两条路径都做了。

这个 bug 之所以潜伏了一天，是因为之前的探测脚本**先自己调用了 `prepareChatBody`** 再把结果交给 `chatStream`——等于把被测的那段逻辑手动跳过了。现在探测脚本一律传原始请求体。

## 请求被拒时的现场记录

上游拒绝一次对话时，插件会把现场写到 `$DSH_HOME/.workbuddy-chat-failure.json`：模型、区域、工具数量与工具名、HTTP 状态、上游响应体（≤8 KB）。**不含任何对话正文**。

上一版只把「工具定义不合规」这句转给你——既不知道是哪个模型、哪套工具触发的，请求体又不进任何日志，所以留了这份记录。

另有三种**不是插件问题**的上游拒绝，换个模型即可：`11158`（账号类型不支持该模型）、`11102`（模型在目录里但服务端未接入）、`14003`（限流）。

补丁落在内联副本的 `lib/host-heartbeat-DpaqHdXw.js`，细节见 [`vendor/dsh-workbuddy-connect/PATCH.md`](vendor/dsh-workbuddy-connect/PATCH.md)。

## 已知限制

- 积分读取真实查询计费接口，但**只读**，不消耗积分。
- 模型目录的可用性取决于上游对当前账号的返回；未登录时不展示任何模型（而不是展示只能用失败的占位列表）。
- 推理档位检测（`dsh-workbuddy-connect` 会发真实请求探测）在本插件里**没有**开放：它确定会消耗积分，属于需要单独授权的动作。
- 本插件与 `dsh-workbuddy-connect` 同时启用会争用同一组 provider id（`workbuddy` / `workbuddy-ai`），后者会注册失败。
